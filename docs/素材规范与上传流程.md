# 素材规范与上传流程

## 1. 先理解两个维度

本项目现在把“机器人系列”和“展示类型”分开管理：

- `category`：机器人/产品系列，例如 `bai-suzhen`、`menglan`。
- `type`：这个内容属于什么展示类型，例如 `dialogue`、`detail`、`fullbody`。

因此白素贞全身展示应写成：

```json
{
  "category": "bai-suzhen",
  "type": "fullbody"
}
```

而不是：

```json
{
  "category": "fullbody"
}
```

网页顶部一级页签只按 `category` 展示：

```text
全部 | 演示机器人 | 白素贞 | 梦岚 | ...
```

“全部”是前端自动汇总，不需要在 JSON 中创建 `all` 分类。每条内容同时会出现在“全部”和它所属的机器人系列页中。

卡片左上角显示 `type` 对应的展示类型，例如“全身展示”“身体局部特写”“对话展示”。

---

## 2. 素材核心规范：固定比例，不固定像素

你不需要保证每张图、每个视频完全相同的分辨率，只需要尽量保持统一比例。

### 产品封面 / 产品图片
- 比例：**3:4**
- 推荐：**1200×1600**
- 最低建议：**900×1200**
- 可直接使用：900×1200、1200×1600、1500×2000、3024×4032

网站完整显示主体，不会为了铺满卡片强行裁头、裁脚。

### 视频 / 视频 Poster
视频允许两种主流方向，网站会根据视频实际宽高自动适配：

**竖屏视频**
- 比例：**9:16**
- 推荐：**1080×1920**
- 最低建议：**720×1280**
- 可直接使用：720×1280、1080×1920、1440×2560、2160×3840

**横屏视频**
- 比例：**16:9**
- 推荐：**1920×1080**
- 最低建议：**1280×720**
- 可直接使用：1280×720、1920×1080、2560×1440、3840×2160

Poster 建议和对应视频保持同方向：9:16 视频配 9:16 Poster，16:9 视频配 16:9 Poster。
如果视频不是 9:16 或 16:9，网站仍会按原始比例完整播放，只会在内容扫描时给出比例警告。

### 推荐视频编码
- 容器：MP4
- 视频：H.264
- 音频：AAC
- 帧率：30fps
- 1080p 推荐码率：约 6~10 Mbps

## 3. 标准内容目录

每个“展示内容”一个独立目录。例如白素贞之后可以有多个内容目录：

```text
public/content/
├─ bai-suzhen-fullbody/
│  ├─ meta.json
│  ├─ cover.jpg
│  ├─ images/
│  ├─ videos/
│  └─ posters/
├─ bai-suzhen-dialogue/
│  ├─ meta.json
│  ├─ cover.jpg
│  ├─ images/
│  ├─ videos/
│  └─ posters/
└─ _template/
```

目录名自动成为内容 `id`，建议只使用英文字母、数字、短横线，例如：

```text
bai-suzhen-fullbody
bai-suzhen-dialogue
menglan-hand-detail
```

---

## 4. meta.json 怎么填写

白素贞全身展示：

```json
{
  "title": "白素贞机器人",
  "category": "bai-suzhen",
  "type": "fullbody",
  "description": "白素贞机器人全身形象与动作展示",
  "tags": ["白素贞", "机器人", "全身", "动作展示"],
  "sort": 10,
  "enabled": true
}
```

字段说明：
- `title`：卡片标题。
- `category`：机器人/系列 id，必须存在于 `site-config.json -> categories`。
- `type`：展示类型 id，必须存在于 `site-config.json -> types`。
- `description`：简介。
- `tags`：用于搜索。
- `sort`：数字越小越靠前。
- `enabled`：`false` 时隐藏。

**不要手写 cover / image / video 路径，也不要填写图片数、视频数。**脚本自动扫描。

---

## 5. 新增一个机器人系列

编辑：

```text
public/data/site-config.json
```

在 `categories` 增加：

```json
{
  "id": "menglan",
  "name": "梦岚",
  "sort": 3
}
```

顶部自动出现：

```text
全部 | 演示机器人 | 白素贞 | 梦岚
```

之后梦岚下面可以有多个内容目录，每个目录的 `category` 都填 `menglan`，但 `type` 可以不同。

---

## 6. 新增展示类型

编辑 `site-config.json -> types`：

```json
{
  "id": "hand",
  "name": "手部展示",
  "sort": 4
}
```

以后某个内容的 `meta.json` 可写：

```json
"type": "hand"
```

## 7. Cover / 图片 / 视频 / Poster 规则

Cover 自动识别：

```text
cover.jpg
cover.jpeg
cover.png
cover.webp
```

图片放入 `images/`，支持 jpg/jpeg/png/webp；视频放入 `videos/`，推荐 mp4，也支持 webm。

文件名会成为页面标题，因此允许中文：

```text
images/01-正面.jpg
images/02-侧面.jpg
videos/01-行走演示.mp4
```

Poster 与视频同名自动匹配：

```text
videos/01-行走演示.mp4
posters/01-行走演示.jpg
```

没有 Poster 时自动使用该内容的 cover。若横屏视频 fallback 到 3:4 Cover，卡片会使用 `object-contain` 完整显示，因此可能出现留边但不会裁切。

---

## 8. 新增内容完整流程

1. 复制 `public/content/_template`。
2. 改成新的内容目录，例如 `public/content/menglan-fullbody`。
3. 修改 `meta.json`：正确填写 `category` 和 `type`。
4. 放入 cover、images、videos、posters。
5. 运行：
   - Windows：`update-content.bat`
   - Linux/macOS：`./update-content.sh`
6. 刷新网页。

自动更新：
- “全部”内容
- 各机器人系列页签数量
- 展示类型标签
- 图片数量 / 视频数量
- 搜索
- 分页

---

## 9. 分页

`public/data/site-config.json`：

```json
"pageSize": 12
```

它表示每页展示 12 个内容卡片。“全部”和每个机器人系列都自动分页，不需要填写总页数。

---

## 10. 不要直接修改 site-data.json

`public/data/site-data.json` 是自动生成文件。

正确修改位置：

```text
public/data/site-config.json
public/content/<内容目录>/meta.json
public/content/<内容目录>/图片视频
```

然后重新运行更新脚本。

---

## 11. 常见错误

- **category 不存在**：先去 `site-config.json -> categories` 增加机器人系列。
- **type 不存在**：先去 `site-config.json -> types` 增加展示类型。
- **meta.json 格式错误**：检查逗号、双引号、括号。
- **视频无法播放**：优先转 MP4 / H.264 / AAC。
- **尺寸警告**：只提醒，不会阻止生成。
- **网站内容没变化**：确认已运行更新脚本，生产环境确认已同步新 `site-data.json` 和 `content/`。

## 12. 列表卡片的媒体展示优先级

“全部”和各机器人系列分类页中的内容卡片，不要求必须同时有图片和视频。系统会自动判断当前内容有什么素材，并按照统一优先级选择卡片预览：

```text
视频 > 图片 > Cover > 占位
```

具体规则：

1. **有视频**：优先按视频内容展示卡片；使用第一个视频的 Poster。没有独立 Poster 时使用该内容的 Cover；两者都没有时显示视频占位图。即使同时有图片，也仍然优先表现视频。
2. **没有视频、但有图片**：使用第一张图片作为卡片预览；如果图片路径异常，再由页面的失败占位逻辑兜底。
3. **没有视频和详情图片、只有 Cover**：使用 Cover。
4. **视频、图片、Cover 都没有**：显示统一占位图。

详情页也遵守相同的内容优先级：

- 有视频：先显示“视频”区。
- 有图片：再显示“图片”区。
- 只有视频：不会再出现空的“图片（0）”。
- 只有图片：不会出现空的“视频（0）”。
- 图片和视频都没有：显示“该内容暂未上传图片或视频”。

> 建议：如果一个内容只有视频，最好同时给视频提供同名 Poster。这样“全部”和系列页中的卡片就能直接显示清晰的视频封面，而不是占位图。


## 13. 视频横竖屏自动适配规则

内容生成脚本会在系统存在 FFmpeg/ffprobe 时自动读取每个视频的宽高：

- 宽 < 高：判定为竖屏，推荐 9:16。
- 宽 >= 高：判定为横屏，推荐 16:9。
- 自动写入 `orientation`、`aspectRatio`、`width`、`height` 到生成的 `site-data.json`。
- 分类详情中的视频缩略卡按该真实比例生成，不会把横屏视频硬塞进 9:16。
- 视频弹窗不固定比例，浏览器按视频真实宽高播放，最大宽度约 92vw、最大高度约 82vh。

如果服务器没有安装 ffprobe：

- 自动生成流程仍正常。
- 视频仍然可以正常播放，并按浏览器读取到的原始比例显示。
- 只是列表视频卡片无法提前知道真实比例，会临时使用默认竖屏卡片比例。

因此生产服务器建议安装 FFmpeg：

```bash
sudo apt install -y ffmpeg
```


## 视频首帧自动生图
如果大部分素材都是视频，可以直接让脚本从视频首帧自动生成图片：

- 输入：`public/content/<product-key>/videos/*.mp4`
- 输出：
  - `public/content/<product-key>/posters/<同名>.jpg`
  - `public/content/<product-key>/images/<同名>.jpg`

示例：

```text
videos/01-行走.mp4
=> posters/01-行走.jpg
=> images/01-行走.jpg
```

命令：

```bash
python tools/extract_video_stills.py
```

默认不覆盖已有图片；如需重建：

```bash
python tools/extract_video_stills.py --overwrite
```

只生成 poster：

```bash
python tools/extract_video_stills.py --only posters
```

只生成 image：

```bash
python tools/extract_video_stills.py --only images
```

`update-content.bat` / `update-content.sh` 已默认先执行这个步骤，再生成 `site-data.json`。


## Windows 视频工具初始化
视频首帧提取依赖 FFmpeg。Windows 第一次使用请先双击：

```text
setup-video-tools.bat
```

它会自动安装 `imageio-ffmpeg`，不要求配置系统 PATH。之后正常使用 `update-content.bat` 即可。

也支持把便携版 FFmpeg 放到 `tools/ffmpeg/bin/ffmpeg.exe`。


## Windows 编码说明
V8 起所有 `.bat` 文件均为纯 ASCII 启动器，真正逻辑在 UTF-8 PowerShell `.ps1` 中执行。安装了 PowerShell 7 时会自动使用 `pwsh`，因此项目路径、产品标题和媒体文件名可以使用中文，不需要修改系统代码页。


# V9：系列分类自动维护

从 V9 开始，**不要手工新增 `site-config.json.categories`**。

每个正式内容目录的 `meta.json` 增加：

```json
"category": "bai-suzhen",
"categoryName": "白素贞",
"categorySort": 100
```

运行 `update-content.bat` / `update-content.sh` 时，脚本会扫描所有正式内容，并自动重建 `site-config.json.categories`。

- 同一系列多个产品使用相同 `category` / `categoryName`。
- `categorySort` 允许重复；相同系列出现多个值时取最小值。
- 如果同一个 `category` 出现不同 `categoryName`，脚本会警告并保留第一个名称。
- 如果新系列不填写 `categoryName`，脚本会使用 `category` ID 作为显示名并给出警告。
- 没有任何正式内容时，`categories` 会自动变为空数组。

`types` 仍手工维护，因为它代表固定的展示类型定义。

## 正式素材模式

V9 源码包已经移除全部演示产品和示例媒体，只保留 `_template`。你本地已有的正式素材直接复制到 `public/content/` 即可。


## V12：分类名称自动读取 title

`meta.json` 中：

```json
{
  "title": "胸部腹部特写",
  "category": "xiongbu-fubu",
  "sort": 101,
  "type": "detail"
}
```

含义：

- `category` 仅用于内部 ID、路由和数据关联。
- 顶部页签显示名称默认读取 `title`。
- `categoryName` 现在是可选字段；只有当分类名称需要与 `title` 不同时再填写。
- `categorySort` 也是可选；缺省时使用 `sort`。

如果同一个 `category` 被多个产品共用，并且它们的 `title` 不同，脚本会提示警告，并优先采用 `sort/categorySort` 更小的产品名称。为了固定名称，可给这些产品填写相同的 `categoryName`。


## V13：横竖素材混合与 mediaOrientation
同一个产品目录中的媒体允许混合：

```text
videos/
├─ 胸部腹部特写1.mp4   # 横版 16:9
└─ 胸部腹部特写2.mp4   # 竖版 9:16

posters/
├─ 胸部腹部特写1.jpg   # 横版 16:9
└─ 胸部腹部特写2.jpg   # 竖版 9:16

images/
├─ 胸部腹部特写1.jpg   # 横版 16:9
└─ 胸部腹部特写2.jpg   # 竖版 9:16
```

推荐让脚本自动识别；如果需要手工锁定方向，在 `meta.json` 中增加：

```json
"mediaOrientation": {
  "胸部腹部特写1": 0,
  "胸部腹部特写2": 1
}
```

`0=横版16:9`，`1=竖版9:16`。名称不带扩展名，并自动应用到同名 video/poster/image。
