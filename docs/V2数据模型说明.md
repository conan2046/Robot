# V2 数据模型说明

V2 修正了 V1 中“系列”和“展示类型混在 category”里的问题。

## 正确关系

```text
全部
├─ 演示机器人 · 对话展示
├─ 演示机器人 · 身体局部特写
├─ 演示机器人 · 全身展示
└─ 白素贞 · 全身展示

白素贞
└─ 白素贞 · 全身展示
```

以后如果白素贞还有其他内容：

```text
白素贞
├─ 全身展示
├─ 身体局部特写
└─ 对话展示
```

每一条内容分别建一个目录：

```text
public/content/bai-suzhen-fullbody/
public/content/bai-suzhen-detail/
public/content/bai-suzhen-dialogue/
```

三个目录的 `category` 都是 `bai-suzhen`，但 `type` 分别不同。

## 字段定义

```json
{
  "category": "bai-suzhen",
  "type": "fullbody"
}
```

- `category` = 机器人/系列
- `type` = 展示类型
- `全部` = 前端自动汇总，不写入 category

## 媒体预览选择规则

每条内容可以只有视频、只有图片，或者二者都有。列表卡片自动选择代表素材，固定优先级：

```text
视频 > 图片 > Cover > 占位
```

如果同时存在图片和视频，卡片永远优先表现视频；详情内也是视频区在前、图片区在后，空的媒体区不会显示。


## V4 视频比例扩展

展示类型和机器人系列的数据模型不变。视频媒体层新增自动比例信息：

```json
{
  "title": "动作展示",
  "url": "/content/.../videos/动作展示.mp4",
  "poster": "/content/.../posters/动作展示.jpg",
  "orientation": "landscape",
  "aspectRatio": 1.777778,
  "width": 1920,
  "height": 1080
}
```

`orientation` 可能为 `portrait` 或 `landscape`。这些字段由内容扫描脚本自动生成，不需要在 `meta.json` 中填写。
